# 悬浮体 · WebXR

伸手进去，搅动一团悬浮的粒子。手停下后它继续旋，慢慢停。

**▶ [打开](https://zhao0424.github.io/webxr-todo/)** — 电脑上用鼠标，头显里用手。

零依赖：一个 HTML 文件，原生 WebGL2 + WebXR Device API，没有任何框架或 CDN。

## 操作

| | 电脑 | 头显 |
|---|---|---|
| 搅动 | 移动鼠标 | 手伸进去划 |
| 聚拢 | — | **握拳**（攥紧的手会变亮；半握半吸） |
| 注入 | 按住左键 | 捏合（两只手可以同时） |
| 视角 | 右键拖拽 / 滚轮 | 走动、转头 |
| 参数面板 | `H` 或右下角「参数」 | — |
| 重置 | `R` | — |

无人操作 6 秒后，会有一只看不见的手接管慢搅。

四种风格：等离子 / 能量核心 / 磁流体 / 水墨。前三种是黑底发光，水墨是宣纸底的乘法混合。

## 设备支持

- **电脑浏览器** — 完整可用（鼠标交互）
- **Meta Quest** — Quest Browser 里点「进入 VR」，原生手部追踪
- **手机** — 可以玩桌面模式，进不了 VR
- 其他 WebXR 头显视其手部追踪支持而定；没有手追时自动回落到手柄

WebXR 需要 HTTPS 或 localhost。

## 怎么做的

两层分离：

```
模拟层（浮点纹理 ping-pong + MRT，与视角无关，双眼只算一次）
  posTex   xyz 位置 + w 寿命
  velTex   xyz 速度
  histTex  环形缓冲，12 个槽位 = 拖尾
渲染层（屏幕分辨率）
  背景 → 手（点精灵）→ 粒子（点精灵 + 混合）
```

状态放在粒子里，不放在体素里——64³ 的体积对丝缕太糙，128³ 又扛不住立体 raymarching。

**三个关键决定：**

**1. 用叉积，不是直接加速度。** 这一行决定了是"搅"还是"吹"：

```glsl
acc += cross(handVel, r) / (dot(r,r) + 0.0006) * falloff * strength;
```

叉积让粒子绕着手的运动轴转，手划过之后继续卷。直接加 `handVel` 是推开，完全不是一回事。

**2. 用混合方程本身做色调压缩。** 发光风格用 screen 混合 `(ONE, ONE_MINUS_SRC_COLOR)`：

```
dst = src + dst*(1-src) = 1 - (1-src)(1-dst)
```

纯加法 `(ONE, ONE)` 在密集处会冲过 1.0 硬截断成一坨死白。screen 渐近收敛到 1，等于把
tonemap 做进了混合方程，省掉一整个 HDR RT + tonemap pass。而且它可交换可结合，和水墨的
乘法混合一样**与绘制顺序无关**——三维半透明的排序问题直接消失。

**3. 速度场用旋度噪声。** 势场是 `p += sin(p.yzx * f) / f` 那套多倍频正弦置换（swizzle 是
流体感的来源），取旋度后无散度，粒子不会堆积也不会凭空消失，**省掉整个压力投影**。

## 两个 XR 特有的坑

- **残影必须几何化。** 生成艺术常用的"不清屏、盖半透明层"在 XR 里会随头动糊成一片。
  这里的拖尾是世界空间的历史位置，不是帧缓冲残留。
- **噪声要 hash 在世界空间视线方向上**，不能用屏幕坐标，否则双眼拿到不同的颗粒，
  在头显里闪得眼睛疼。
- 另外：**不要在 XR 里硬写世界坐标**。没有地面追踪的 runtime 会把 `local-floor` 的原点
  报在头的位置，硬写 `y = 1.25` 就跑到头顶一米多去了。这里是进入时按当前头姿摆在正前方。

## 性能

主要开销是 fill rate（点精灵的填充），不是 ALU 也不是带宽。面板底部实时显示
`fps · 粒子数 × 拖尾段数 = 总点数`。

跑不动时按这个顺序砍：**拖尾长度 → 笔触大小 → 粒子量**。笔触大小是平方级影响填充率，
最敏感。
