# 悬浮体 · WebXR

伸手进去，搅动一团悬浮的粒子。手停下后它继续旋，慢慢停。

**▶ [打开](https://zhao0424.github.io/webxr-todo/)** — 电脑上用鼠标，头显里用手。

零依赖：一个 HTML 文件，原生 WebGL2 + WebXR Device API，没有任何框架或 CDN。

## 操作

| | 电脑 | 头显 |
|---|---|---|
| 搅动 | 移动鼠标 | 手伸进去划 |
| 聚拢 + 拖动 | — | **握拳** — 光点被收进掌心，整团跟着手走 |
| 注入 | 按住左键 | 捏合（两只手可以同时，各注各的） |
| 刹车（隧道） | — | **握拳** — 减速到 25% |
| 视角 | 右键拖拽 / 滚轮 | 走动、转头 |
| 参数面板 | `H` 或右下角「参数」 | — |

无人操作 6 秒后，会有一只看不见的手接管慢搅。

## 三种形态

**渐变** — 在三组参数之间连续循环插值。不只是换色板：黏滞 0.34→1.6、湍动 0.26→0.05
差到五倍，所以介质会从躁动的等离子慢慢变得粘稠、贴住场线，再变回来。

**黑洞** — 吸积盘 + 开普勒微分自转（越靠内转越快）+ 事件视界（掉进去的粒子被吞掉，
从外缘重新流入）+ 多普勒集束 + 光子环 + 引力透镜的次级像 + 三个自由翻滚的环。
伸手可以把物质推进视界，也可以推着三个环往任意方向转。

**隧道** — 一条无限长的绿激光走廊，构图是几条极长的直线精确汇聚到视野正中的一点。
四层各管一件事：**贯穿轨**（从 700 米外拉到身后，严格平行于轨道所以精确汇到灭点，
静止不动 —— 它是骨架）、**横档**（挂在轨上的短横杠，速度感由它给）、**流线**（很暗的
细线，只做纹理）、**结构**（门 / 环 / 弧 / 螺旋，每 7 米现算一组，留白占大头）。
每半分钟换一「幕」，强调色、密度、速度一起变。人站着不动，走廊自己压过来。握拳 = 刹车。

## 设备支持

- **电脑浏览器** — 完整可用（鼠标交互）
- **Meta Quest** — Quest Browser 里点「进入 VR」，原生手部追踪
- **手机** — 可以玩桌面模式，进不了 VR
- 没有手追时自动回落到手柄（扳机 = 注入，侧键 = 摆位）

WebXR 需要 HTTPS 或 localhost。

## 怎么做的

```
模拟层（浮点纹理 ping-pong + MRT，与视角无关，双眼只算一次）
  posTex   xyz 位置 + w 寿命
  velTex   xyz 速度
  histTex  环形缓冲 = 拖尾
渲染层
  粒子 → RGBA16F（纯加法，能量无上界）
       → 逐级降采样 1/4 → 1/8 → 1/16
       → 合成 1 - exp(-(scene + bloom) × exposure)
```

状态放在粒子里，不放在体素里——64³ 的体积对丝缕太糙，128³ 又扛不住立体 raymarching。

**用叉积，不是直接加速度。** 这一行决定了是「搅」还是「吹」：

```glsl
acc += cross(handVel, r) / (dot(r,r) + 0.0006) * falloff * strength;
```

叉积让粒子绕着手的运动轴转，手划过之后继续卷。直接加 `handVel` 是推开。

**速度场用旋度噪声。** 势场是 `p += sin(p.yzx * f) / f` 那套多倍频正弦置换（`.yzx` 那个
swizzle 是流体感的来源），取旋度后无散度，粒子不会堆积也不会凭空消失——省掉整个压力投影。

**水流是层流，不是湍流。** 各向同性的湍流云怎么调都只是烟。隧道里的粒子走管道流：
抛物线速度剖面（中心快、贴壁慢）+ 绕轴螺旋，剪切一出来就是水。

**流线要画成带子，不是点。** 点精灵在 90Hz 的头显里会散成虚线 —— 11m/s ÷ 90 = 12cm 的
间距，而点只有几毫米。改成在相邻两个历史槽之间拉一条正对相机的带子，速度再快也是连续的。
带子必须按距离衰减：远处的流线在屏幕上全汇到灭点那一个点、密度暴涨，而线宽有像素下限
撑着不会变细，不衰减就会烧成一坨死白。

**循环在着色器里做。** 横档和流线按 `aWrap` 对 z 取模折回 —— 无限长、每帧零数据更新，
而且是在雾里出现，看不见弹出。只有结构那一层需要 CPU 回收。

**走廊在动，人不动。** XR 里移动相机就是晕车的配方。推进做成把整条走廊往人身上推：
着色器里 `aA.z + uRideZ` 一行，每帧只改一个 uniform，几千段线的实例数据一个字节都不用碰。

**线要自己扩成四边形。** `gl.lineWidth` 在 ANGLE 上恒为 1px，所以每段线在顶点着色器里
扩成正对相机的四边形。扩张放在**视图空间**（法线取 `cross(线方向, 到该点的视线)`），
不是裁剪空间——走廊会从人身上穿过去，裁剪空间的做法一碰到 `w<0` 就翻面。

**引力透镜画的是次级像。** 粒子渲染器不能弯折光线，但可以把「光绕过洞之后看起来来自哪个
方向」直接画出来：在 相机–洞–粒子 构成的平面内，用罗德里格旋转把视线方向转到光子球的角
半径附近。盘的远侧因此被拱到洞的上方和下方——那条光弧才是「像黑洞」的来源，不是多普勒。

## 踩过的坑

- **加法累积必须接 tonemap。** 密集处会冲过 1.0 硬截断成一坨死白。
- **稀疏采样做辉光会留下结构性伪影。** 忘了每像素抖动起始角，每个亮点就被复制成 N 个
  排成螺旋的副本；加了抖动之后仍有采样噪声（稀疏光源上方差极大），在 1/4 分辨率上放大
  回来就是马赛克。最后换成逐级降采样才彻底干净——**这类问题要换算法，调参数没用**。
- **XR 里不要硬写世界坐标。** 没有地面追踪的 runtime 会把 `local-floor` 的原点报在头的
  位置，硬写 `y = 1.25` 就跑到头顶一米多去了。
- **不要把功能绑在 `squeeze` 上。** runtime 对「握拳」也会发 `squeeze`，于是握拳吸附的
  同时触发了别的动作。手势自己从关节算（指尖到腕的距离，用掌骨长归一化）更可控。
- **残影必须几何化。** 生成艺术常用的「不清屏、盖半透明层」在 XR 里会随头动糊成一片。
- **立体下辉光要按眼夹住采样范围**，否则左眼的光会漏进右眼。

## 性能

主要开销是 fill rate。面板底部实时显示 `fps · 粒子数 × 拖尾段数 = 总点数`。
跑不动时按这个顺序砍：**拖尾长度 → 笔触大小 → 粒子量**。笔触大小是平方级影响填充率。
