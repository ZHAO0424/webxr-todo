# 名画入深：用 WebXR 把大师画作还原成 3D —— 调研与计划

## 1. 结论：可行，而且浏览器端就能做出第一版

- **深度**：单目深度估计模型（Depth Anything V2）已经有 ONNX 版本，可以用 transformers.js 直接在浏览器里跑。不需要服务器，也没有 API 费用。
- **画源**：Wikimedia Commons 上的经典名画是公有领域，`upload.wikimedia.org` 的缩略图带 `Access-Control-Allow-Origin: *`，可以作为 WebGL 纹理加载，也可以送进模型。实测 8 幅图都能拿到 1280px 版本。
- **显示**：three.js 的 WebXR 支持 VR 和 AR。眼镜上只用正前方大约 40° 视锥、一臂距离以内的空间，刚好对应“站在画前看”的体验，单视角深度方法最致命的短板（侧面没有内容）被这个约束避开了。

## 2. 技术路线对比

| 路线 | 做法 | 优点 | 短板 | 适用阶段 |
|---|---|---|---|---|
| A. 深度浮雕 / 2.5D | 单图深度 → 位移网格或点云 | 纯前端、秒出、所有画都能用 | 被遮挡的地方没有内容，侧看会拉伸 | **MVP（已实现）** |
| B. 分层深度图（LDI）+ 补全 | 按深度切层，用 inpainting 补出背后被挡住的内容 | 能小幅走动、侧看，有视差 | 补全模型要跑在服务端；画风可能不一致 | 第二阶段 |
| C. 单图 → 3D 世界 / 高斯泼溅 | World Labs Marble、WonderWorld 一类生成式方法 | 真正可以“走进画里” | 有成本（Marble 额度暂时不动）；生成内容会偏离原作 | 第三阶段，挑几幅精品 |
| D. 人工分层建模 | 美术手动抠层并建模 | 质量最高，忠实于原作 | 每幅画都要投入人力 | 只做展示用的精品 |

已有参考：
- Fraunhofer 2025 年的工作，把历史彩色照片（autochrome）做成分层深度图和网格，再用 WebXR 展示，路线与 B 相同。
- CRS4 做过单张全景图到立体 VR 的工作（深度 + GAN 补全），也是 WebXR 查看器。
- 没有找到专门针对名画做“浏览器走进画里”的现成工具，这块可以做出差异。

## 3. 关键难点

1. **画作的深度不是照片的深度**。浮世绘、中世纪画有平面化或反透视，点彩、厚涂的笔触纹理会被模型误读成几何。Depth Anything 对写实油画（Friedrich、Vermeer）效果最好，对《神奈川冲浪里》《呐喊》会比较“随意”。对策：提供纵深滑杆和分层模式，让风格化的画以“立体书”方式呈现，不硬做真实空间。
2. **深度断层处的拉伸**。前后景交界处会出现被拉长的“橡皮筋”三角形。MVP 在像素着色器里检测深度突变并丢弃，把这些地方撕开。真正补上背后的内容要等 B 路线。
3. **视点约束**。单视角深度只在正面 ±20–30° 内可信，所以画放在正前方一臂之内，不让用户绕到背后。
4. **版权**。只用公有领域作品，页面上标注来源（Wikimedia Commons）。上传功能只在本地处理，不外传。

## 4. MVP（已实现：`index.html`）

- 预置 8 幅名画：星月夜、神奈川冲浪里、雾海上的旅人、戴珍珠耳环的少女、大碗岛、印象·日出、蒙娜丽莎、呐喊。也可以上传自己的图片。
- 深度用 Depth Anything V2 Small 在本地计算。有 WebGPU 就用 WebGPU，没有就回退到 WASM（q8 量化）。无头测试时 WASM 下一幅画约 3.5 秒，模型第一次加载后走浏览器缓存。
- 三种呈现模式：
  - **浮雕**：连续位移网格，配纵深滑杆（0–60cm）。深度断层处撕开，可以关掉。
  - **分层**：深度量化成 7 层，效果像立体书或剧场布景，适合风格化的画。
  - **点云**：每个点是一粒“颜料”，带轻微呼吸动画，手指靠近会把颜料拨开。
- XR 交互：扳机或捏合切换模式，握把换下一幅画。AR 模式下背景透明，画框就挂在真实空间里。

## 4.5 进度（2026-10-16）：P1 + P2 已完成

- **离线烘焙 `bake/bake.py`**（venv 在 `bake/.venv`，模型在 `bake/models`）：
  - 深度换成 Depth Anything V2 **Large**（int8 ONNX），再做保边双边滤波，压掉笔触被误读成的几何噪声。
  - 用一维 k-means 把深度切成 4 层。
  - 用 LaMa（OpenCV Zoo ONNX）补全每层被前景挡住的区域：最远层补成完整背景板，中间层只在自身周围 6% 图宽内延展；只在需要补的区域的包围盒里跑，补得更清晰。
  - 每层深度用 Telea 向外延展，并限制在本层深度上界以内，保证排在更近层的后面。
  - 产出放在 `data/<slug>/`，8 幅合计约 16 MB，烘焙一幅约 30 秒（CPU）。
- **页面**：
  - 预置画直接读烘焙结果，不再下载浏览器端模型，也不再依赖 Wikimedia。
  - 新增**视差**模式（LDI）：侧着看时，前景背后露出的是补全的画面，不再是拉伸的条纹。
  - 每幅画有预设的纵深和默认模式（写实的画默认视差，浮世绘和呐喊默认分层）。
  - XR 里画框下方有缩略图条和模式按钮，射线加扳机/捏合可以选，手指直接戳也可以；桌面上鼠标点击也能用。
  - 点云模式内缩 0.4%，去掉边缘的杂点。
  - 上传的图仍然走浏览器端 Small 模型实时估计，没有视差模式。
- **已知问题**：
  - LaMa 输入固定 512，大块补全会偏糊。补出来的区域只在侧看时露出，可以接受。
  - 《雾海上的旅人》中间层在岩石边缘有一圈偏黄的补全。
  - 以上都只在无头浏览器里验证过，还没上眼镜实测。

## 5. 后续阶段

| 阶段 | 内容 | 产出 |
|---|---|---|
| P1 打磨 | 深度图双边滤波，减少笔触噪声；为每幅画预调纵深和分层数；XR 内放一个 3D 选画面板；边缘衰减，去掉点云边缘的杂点 | 可以给同事试玩的 demo |
| P2 LDI | 离线 Python 管线：Depth Anything V2 Large → 按深度切 3–5 层 → 对每层被挡住的区域做 inpainting（风格一致的补全）→ 导出分层 PNG 和深度 → 网页加载 | 可以左右挪步，有真实视差 |
| P3 走进画里 | 挑 2–3 幅（建议选空间感强的：雾海上的旅人、大碗岛），用 Marble 或 WonderWorld 生成高斯泼溅场景，用 Spark / gsplat.js 在 WebXR 里渲染，从“画框模式”过渡到“画中世界” | 展示用的精品 |
| P4 叙事 | 画家生平、笔触解说的语音导览；“画框 → 浸入”的转场；多人共看 | 完整体验 |

## 6. 运行方式

- WebXR 要求页面通过 https 或 localhost 打开。在本目录运行 `python -m http.server 8000`，再打开 `http://localhost:8000`。
- 在眼镜或颈环上看，可以用 `adb reverse tcp:8000 tcp:8000` 把端口转过去，然后在设备浏览器打开 localhost；也可以部署到任意 https 静态托管。
- 依赖 CDN（three.js、transformers.js、Hugging Face 模型、Wikimedia 图片），需要联网。

## 7. 评估

- 主观评价：同一幅画对比平面、浮雕、分层三种方式，看“空间感”和“与原作的忠实度”。
- 技术指标：深度推理耗时、XR 帧率（点云约 26 万点，网格约 16 万三角形）、在眼镜上的加载时长。
